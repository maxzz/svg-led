The loop is caused by Monaco's hover tooltip, not by a menu. The tooltip "Close (Escape)" appears over the find widget's X button, so it sits on top of the button it describes.

**Cause:** Monaco shows that tooltip when you hover the X. The tooltip is placed over the X, so the mouse lands on the tooltip instead of the button. The tooltip hides when the mouse leaves it, the mouse is then back over the X, and the tooltip shows again. That cycle is the opening and closing you see, and the click never reaches the X.

**Fix:** I added a rule to `src/assets/styles/index.css` that makes Monaco's hover tooltips click-through:

```css
.context-view:has(.monaco-hover),
.monaco-hover,
.workbench-hover,
.workbench-hover-container {
    pointer-events: none;
}
```

**Verified:** On `localhost:3001` I hovered the X so the tooltip showed, then clicked it. The find widget closed, and no tooltip came back. I had to apply the rule to the page at runtime to test it, then removed that test style. The new rule is in the stylesheet, but I didn't reload the page to confirm it's picked up from the file.

**Trade-off:** Monaco tooltips across the app become non-interactive. That's fine for this editor since the tooltips are informational, but any future tooltip that needs a click won't work. The rule is also global, so it applies to any `.context-view` that holds a Monaco hover.
