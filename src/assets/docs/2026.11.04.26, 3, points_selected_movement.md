A press that misses a 4px anchor box, or lands on the stroke near a selected point, therefore moves the entire path. When points are selected in Direct Selection, pressing on that element now drags only those points, not the whole path. The type check passes and the existing tool tests pass (63/63). I did not test the drag in the running app, and I did not add a new test for this path.

**What was wrong:** the anchor-drag code already moved only the selected points. The problem was in the element branch of `onPointerDown` in `src/tools/tool-3-points/0-factory-points.ts`. A press that landed on the path body, including a miss on the small 4px point box, started a whole-element move, even with points selected.

**The fix:**
- If the pressed element has selected points, the press now starts the same drag as a point press, moving only the selected points.
- If a selected point is within about 6px of the pointer, that point is the one that snaps to targets during the drag.
- Shift-click on the body still toggles the element in the selection, as before.

One behavior change to be aware of: with points selected on a path, dragging anywhere on that path moves those points. To move the whole path while its points are selected, you would need to use the Select tool or deselect the points first.
