# File modification indicator
_Exported on 11/9/2026 at 20:17:28 PST from Cursor (3.29.15)_

---

**User**

An indicator must be added to show that the contents of a file have been modified during the current session. 
The attached screenshot illustrates the indicator's location: it appears on the island between Undo/Redo buttons (and should not change the size of this island, i.e. be as overlay) whenever the file's content has changed.
Clicking this indicator triggers a save operation to local storage.
 
Additionally, the "Save" and "Save As" commands—located on the main command island—should be disabled if no changes have been made. 
Furthermore, if the "Format SVG" operation is triggered within the Monaco editor context menu, the indicator should reflect that the content has been modified and requires saving to local storage.

**Decision for you:** the indicator only makes sense if localStorage is no longer written on every change. The old autosave wrote 600ms after each edit, so the dot would clear almost immediately. I replaced it with a manual save, which means **unsaved edits are lost if the tab is closed before you click the dot**. I didn't add a close-tab warning. If you want one, it's a small `beforeunload` addition.

**What changed**

- **Two "unsaved" flags** (`modifiedState` in `2-doc-history.ts`): `storage` drives the indicator, `file` drives Save and Save As. Any change marks both. A load (startup, Open, sample) clears both.
- **Indicator** (`2-2-island-undo.tsx`): a small accent dot absolutely positioned at the bottom-center of the Undo/Redo island, so the island's size doesn't change. It shows only when `storage` is modified. Clicking it writes to localStorage via `saveDocToStorage()` in `1-autosave.ts`, which clears the flag.
- **Save and Save As** (`0-all-commands.ts`): `enabled` is `modifiedState.file`. Menus, the command palette, and Ctrl+S already honor `enabled`, so they're disabled too. A successful file save clears the `file` flag (`5-file-io.ts`).
- **Format SVG** (`1-monaco-host.tsx`): with code sync on, the edit already flows into the document and marks it modified. With sync off, the document wouldn't change, so the action now calls `applyCodeToCanvas()` to push the formatted text into the document.
- **Two existing commits were treated as loads**, so I changed their origin to a user origin: Reset canvas and inserting a scrap (`9-types-scraps.ts`). Otherwise they would not have set the indicator.

**Behavior you might not expect**

- Undoing back to the saved state still shows the indicator, since the flag tracks "changed since last save", not content equality.
- Save and Save As stay disabled until something changes, even on a freshly opened file.
- Text typed in the code panel while sync is off doesn't mark the document modified. That was already the case, and I left it alone.
