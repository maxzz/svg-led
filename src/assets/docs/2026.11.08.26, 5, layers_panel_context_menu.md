**How it works.** There is one menu, wrapped around the tree. A right-click finds the row under the pointer from its existing data attributes and selects it. The menu then lists the commands registered for that kind of row. If several rows are already selected and you right-click one of them, the selection is kept. Right-clicking empty space or the table of declarations under a class opens no menu.

**Adding a command later** means adding one entry to the `layersMenuCommands` list in `3-menu-commands.ts`. Each entry says which kinds of row it appears for, its menu section (sections are separated by a line), when it's enabled, and what it does. TypeScript narrows the target to those kinds, so a class command gets the style index and class name directly.

**State.** All state is in Jotai atoms: one for the row the menu was opened for, derived atoms for the target and its items, and write atoms to open the menu and run a command. The components have no `useEffect`, `useCallback` or local React state. The menu items read the store only while the menu is open.

**Files.** The new code is in `src/components/1-workspace/6-layers-panel/5-context-menu/`, plus `src/svg-core/7-ops/8-defs-item-edits.ts` for the markup and attribute edits, with its tests. I changed existing code in only two places: wrapping the tree in `0-layers-panel.tsx`, and exporting two private helpers (`styleAt`, `takeClassRules`) from `7-defs-items.ts`. The menu UI reuses the canvas menu's item and separator helpers and the shadcn context menu.

Choices I made that you may want changed:

- **Apply scope:** it changes every element at any depth under the `<defs>` element's parent that lists the class, not only its direct siblings.
- **Apply result:** each element loses the class name, but the CSS rule stays until you delete it.
- **Which declarations Apply uses:** a commented-out declaration or a turned-off class is skipped.
- **Where the values go:**
  - A standard SVG presentation property becomes an attribute and overwrites an existing one, since a class beats an attribute.
  - A property that already exists in the element's inline `style` is left alone, since inline style beats a class.
  - Any other property, or an `!important` one, goes into `style`.
- **When items are disabled:**
  - **Isolation Mode** is disabled for the object that is already isolated.
  - **Delete** is disabled for a locked layer and for the isolated object itself.
- **What Delete leaves behind:** deleting a class's last rule leaves an empty `<style></style>`, which still shows in the tree.
