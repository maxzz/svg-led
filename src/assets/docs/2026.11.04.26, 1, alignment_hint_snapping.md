# Alignment hint snapping feature
_Exported on 11/4/2026 at 17:28:22 PST from Cursor (3.28.7)_

---

**User**

In the "Direct selection" mode, when snapping is enabled, an "alignment hint" (marked with a crosshair) appears. 
If the cursor is positioned near this crosshair on an alignment line, then upon releasing the mouse, the object should snap not to the grid, but to the specific point near the crosshair where the mouse was released.

In Direct selection, dragging an anchor with snapping on now lands exactly on a target point when the pointer is released near its crosshair. It no longer falls back to the grid. The existing snap tests pass (12/12) and the type check is clean. I did not run the app or add a test for the new path, so the drag behavior is untested by hand.

**Cause:** `moveAnchorsGesture` in `src/tools/tool-3-points/0-factory-points.ts` rounded the pointer offset to the grid first, then ran point snapping on that rounded position. If the rounded position was outside the snap threshold of the target point, the snap was missed and the anchor landed on the grid.

**Fix:**
- `src/tools/2-2-core-snapping-points/4-point-snap-session.ts`: new `updatePointSnapOverGrid`. It checks the raw pointer position against point targets first, and if one is within the threshold it snaps to that point exactly. Otherwise it uses the existing guide snapping on the grid-snapped position, so single-axis alignment still works as before.
- `src/tools/2-2-core-snapping-points/1-point-snap-engine.ts`: `nearestPoint` is now exported so the session can use it.
- `src/tools/2-2-core-snapping-points/index.ts`: exports the new function.
- The anchor drag uses the new function. It is skipped for constrained (Shift) drags, since point snapping only applies with both axes free.

Handle drags already used the raw pointer position, so they were not affected.
