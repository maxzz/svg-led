# Context menu expand command
_Exported on 11/1/2026 at 20:12:48 PST from Cursor (3.27.22)_

---

**User**

Once one or more paths have been selected, the "Expand" command should be added to the context menu; this command will allow to transform the appearance of the paths—taking their strokes and fill  into account—into a new path.
If the selected objects have no strokes, the command will do nothing. 
If only some paths have strokes, those paths will be expanded.

---

**Cursor**

I'll look through how path selection and the context menu work so Expand can turn stroked paths into new outline paths.

Expand will turn a stroked path’s painted stroke and fill into real path geometry, and show up in the context menu when paths are selected. I’ll add that command and the outline conversion next.

A finished dash was being treated as a zero-length dash. I’ll correct that before adding tests.

Strokes in this file come from CSS classes, so Expand has to read those rules or it would leave the artwork unchanged.

**Expand** is now in the canvas context menu whenever the selection includes a path. It bakes that path's painted stroke into real filled geometry.

- A path with no stroke is left as it is. If nothing selected has a stroke, **Expand** is disabled.
- If only some of the selected paths have strokes, only those paths change.
- The outline follows the stroke width, caps, joins, miter limit, and dashes. A stroke that comes from a class in a `<style>` block is included.
- When the fill and the stroke are the same opaque color, they become one path and the stroke is removed.
- When the colors differ, the original fill stays and the stroke outline is added as a second path on top of it, so both paints remain.

I tried this on the white cursor path (fill and stroke `#fff`, width 2). Its box grew by the stroke on every side, from 9.4×13.65 to 11.4×15.65, and the stroke was cleared. That change was undone, so the document is back to the path you had.

**Cursor**

I'll look at how the properties panel decides which actions to show, so Expand can appear there under the same kind of conditions.

The Actions bar already shows a command only when it applies to the selection, and the command itself decides whether the button can be clicked. Expand will follow that: it shows when a path is selected, and stays disabled when none of those paths have a stroke.

**Expand** now sits in the Actions section of the properties panel when the selection includes a path. It is placed after Convert to path.

The button is enabled only when at least one of those paths has a stroke, the same rule as the context menu. A rectangle or other shape does not show it. A path with no stroke still shows the button, but it stays disabled and does nothing.
