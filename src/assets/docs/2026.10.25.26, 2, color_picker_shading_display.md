# Color picker shading display
_Exported on 10/25/2026 at 15:54:58 PDT from Cursor (3.27.12)_

---

**User**

When white or black is selected in the color picker pop-up, the color-shading section appears empty, making it difficult to see (see acreenshot). 
If white is selected, the shades section should display a gradient from white toward black (or perhaps toward a shade of gray, using small and reasonable, incremental steps). 
Similarly, if black is selected, the section should transition from black toward a lighter color.

**Cursor**

The shades row only renders for palette families. White and black are fixed colors with no `shades`, so the row falls back to empty placeholders. I'll give those two cells their own gray ramps and route the shades row through them.

Now the palette data, the ramps, and the matching logic.

I updated the color picker so white and black now show a shade row instead of an empty one. I haven't run the dev server or checked it visually, but the file has no lint errors.

The change is in `src/components/1-workspace/2-props-panel/2-props-panel-controls/4-0-color-row.tsx`:

- **White** shows a gray ramp from `#ffffff` down to `#999999` in steps of about 10%.
- **Black** shows a ramp from `#000000` up to `#666666` in the same steps.
- Clicking a shade sets that exact color. The current shade is highlighted, and Shift+1 to Shift+5 work as they do for the other families.

I kept the ramps to mid-gray rather than running all the way to black for white (or to white for black). Each ramp is five values in fixed steps, so the lightest and darkest ends are the exact white and black. If you want the full range instead, the two constants `WHITE_RAMP` and `BLACK_RAMP` are the only things to change.
