I rewrote Offset Path to work the way Illustrator and vectorcraft do. Instead of moving the existing points, it offsets the whole shape outline, then rebuilds clean curves. The type check and all 250 tests pass.

**What it does now**
- **Closed paths:** a positive offset grows the filled shape by the distance in every direction, and a negative one shrinks it. It reads the path's fill rule, so holes shrink as the shape grows and grow as it shrinks.
- **Overlaps and collapse:** parts that grow into each other merge into one shape. Parts narrower than twice the inset disappear. If the whole shape collapses, OK adds nothing and shows the existing "The offset left no geometry" message.
- **Open paths:** these are outlined on both sides, as in Illustrator. The ends follow the Joins setting: square for Miter, round for Round, flat for Bevel.
- **Joins:** I added **Bevel** to the dialog, as in Illustrator. Miter limit is greyed out unless Miter is chosen.
- **Clean results:**
  - A circle stays a circle with 4 smooth points.
  - A rounded rectangle insets to smaller round corners with straight sides, and becomes a plain rectangle once the inset passes the corner radius.
  - Smooth shapes keep only a handful of points.
  - Sharp corners stay sharp.

**How it works.** vectorcraft does this in Rust with a library we don't have. I rebuilt the same approach on `clipper2-ts`, which Expand already uses. Clipper only works with straight-line polygons, so I added a curve fitter that turns its dense result back into Bézier curves. It keeps real corners as corners and long edges as straight lines.

**Changes from what you asked for earlier.** These follow from matching Illustrator:
- The point count no longer stays the same.
- A straight line is no longer thickened on one side only. It gets an outline on both sides, which is what Illustrator produces.

One small difference from Illustrator remains: when a miter goes past the miter limit, Clipper squares the corner off instead of bevelling it.

I checked the results visually on a test sheet of stars, rounded rectangles, a freeform blob, a heart, an open S-curve and a letter "C", each with all three joins at +12 and −12. A path with 300 curve segments offsets in about 8–34 ms, which is fast enough for the live preview.

You were right that it was simplified. It had two problems:

- **Coarse flattening:** curves were turned into straight segments with a tolerance tied to stroke width, up to 0.5 units for strokes 17 units or wider. On wide strokes the steps were visible as facets.
- **No curve rebuilding:** Clipper's outline went into the file directly as `L` commands. vectorcraft rebuilds curves after outlining; ours never did.

**What changed**

- **Finer flattening:** curves are split into steps that are short and turn only slightly, sized to the path and stroke width. The outer edge of a wide stroke is now as smooth as the inner edge.
- **Curve fitting:** each outline ring goes through the same fitter as the new Offset Path. Sharp corners stay corners, straight edges stay single lines, and curved parts become Bézier curves.
  - A rounded rectangle with a 10-unit stroke gives two rings of 4 lines and 4 arcs each (16 anchors total, where the old output had hundreds).
  - A round cap is two quarter-arcs.
- **More even curves:** the fitter now spaces anchors evenly when it can, so symmetric shapes get symmetric anchors. Offset Path benefits from this too.

Everything else about Expand is unchanged: caps, joins, miter limit, dashes, merging fill and stroke of the same color, styles from classes, and inherited styles.

I added a rounded-rectangle regression test to `src/svg-core/tests/expand-stroke.test.ts`. The code changes are in `src/svg-core/7-ops/5-expand-stroke.ts` and `src/svg-core/4-geometry/5-fit-curve.ts`.
