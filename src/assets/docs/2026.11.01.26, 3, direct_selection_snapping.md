**How the snapping behaves**
- **What snaps:** only the point under the cursor snaps, like in Illustrator. If several anchors are selected, the others move with it by the same amount.
- **Order of priority:**
  1. Landing directly on a nearby anchor or visible handle.
  2. Landing on an object's corner, edge midpoint or center.
  3. Lining up horizontally or vertically with anchors and handles.
  4. Lining up with object edges and center lines.
- **Guides and crosses:** each alignment draws a guide from the target to the dragged point, with a cross on the target. When the point lines up on both axes at once, a cross also marks where the two guides meet.
- **Handles:** a dragged handle can line up with its own anchor, which gives a level or vertical tangent. It ignores its own sibling handle, because on a smooth point that one moves with it. Alt-dragging handles out of an anchor snaps the same way.
- **Modifier keys:**
  - With Shift on an anchor drag, the point moves along one axis and snaps only along that axis.
  - With Shift on a handle drag, the 45° constraint turns snapping off.
- **Turning it on:** it uses the existing switches, the "Snap to objects" preference or holding Ctrl during a drag.

**One behavior change:** anchor drags used to snap the box around all selected anchors to other objects' boxes, including equal-spacing guides. That's now replaced by snapping the grabbed point. Moving whole objects still uses the old box snapping.

**Code layout**
- **New folder:** everything is in `src/tools/core-point-snapping/`:
  - `1-point-snap-engine.ts` holds the geometry and priority rules, with no React or state.
  - `2-point-snap-targets.ts` collects targets. It skips hidden or locked elements, objects outside isolation, and whatever is moving in the current drag.
  - `3-point-snap-atoms.ts` holds the state.
  - `4-point-snap-session.ts` holds the three calls the tool makes: start, update and end.
  - `5-point-snap-overlay.tsx` draws the guides and crosses.
- **State:** the state is Jotai, since the tools already use Jotai's `get`/`set`. A private atom holds the result, and the tool changes it through write-only atoms (`setPointSnapAtom`, `clearPointSnapAtom`). A derived atom, `pointSnapScreenAtom`, converts it to screen coordinates, so the guides follow zoom and pan.
- **No React hooks:** the overlay just reads that derived atom, so there are no `useEffect`, `useCallback` or `useMemo` calls.
- **Existing files touched:** the edits to existing code are small. `tool-3-points/0-points.ts` now calls the new module. `3-overlay/index.tsx` renders `<PointSnapOverlay />`. The Ctrl help text in `8-definition-of-modifiers.tsx` is updated.

The snap distance is the same 6 screen pixels the existing snapping uses. Holding Ctrl when you press on an anchor still deletes it, so Ctrl-to-snap only works after the drag has started.
