**Cursor**

The width comes from the palette's `PopoverContent`, not from the element at lines 121–175.

**What's setting it**

- `src/ui/shadcn/popover.tsx` (line 29) gives every popover the base class `w-72` (18rem, 288px).
- The palette's `PopoverContent` at line 42 of `4-0-color-row.tsx` passed `max-w-64` (16rem, 256px). That caps the popover at 256px, so the popover is effectively fixed at 256px.
- The element you selected is a `flex flex-col` div that is a direct child of the popover. Block-level children in a column flex container stretch to the container's width, so it gets the popover's 256px.

**The change**

I changed the palette's popover class from `max-w-64` to `w-auto` (line 42). `cn` uses tailwind-merge, so `w-auto` overrides the base `w-72` and the popover sizes to its content.

**Things to check**

- The hex `<input>` in `HexField` has `grow min-w-0` but no explicit width. Its intrinsic width (about 20 characters by default) now feeds into the popover's content width, so the popover may end up wider than the 5-column grid. If that happens, give the input an explicit width such as `w-24` or `w-full`.
- I haven't run the app to check the rendered width, so this is based on reading the CSS and the component structure.
