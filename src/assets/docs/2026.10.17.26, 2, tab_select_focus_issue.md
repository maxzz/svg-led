When the selected item in this control is changed using the up/down arrow keys, two odd things happen: first, the focus ring moves, and then the background—which displays an animation for the selected item—shifts. 
This creates a significant amount of discomfort and needs to be fixed. 
Perhaps the focus ring could be set to the selected item only after the background animation for that item has finished, or some other, better solution could be implemented.

**Cursor**

The cause is that `focus()` moves the focus ring to the new button immediately, while the shared `layoutId` background spring is still traveling from the old item. The fix I'll make is to draw the focus ring on the sliding highlight itself, so the ring travels with the background instead of jumping ahead of it.

I changed `TabSelect` so the focus ring is drawn on the sliding highlight instead of on the button, which means it moves with the background rather than ahead of it. The project type-checks, but I haven't run it in a browser, so the feel still needs a quick check with the arrow keys.

**What was wrong:** `selectAt` called `.focus()` on the new button right away. The button's own `focus-visible` ring appeared at the destination instantly, while the shared `layoutId` background was still spring-animating from the old item.

**What changed in `src/ui/local-ui/5-tab-select.tsx`:**
- The button now has `group` and `focus-visible:outline-none`, so it no longer draws its own ring.
- The highlight `motion.div` gets `group-focus-visible:ring-[1px] group-focus-visible:ring-ring/50 group-focus-visible:outline-1 group-focus-visible:outline-ring`. It shows the same ring, but only while its button has keyboard focus.

Because the highlight is the element being animated, the ring now travels with the background. Focus still moves to the new tab immediately, so keyboard and screen-reader behavior is unchanged. I didn't use the delayed-focus approach from your suggestion, since it would leave focus lagging behind keypresses and queue up badly with key repeat.

Two things to watch for when you test:
- The ring is now part of the highlight, so it gets the same `shadow-sm` and scale treatment as the background during the animation.
- The highlight only exists on the selected item. That's fine today because focus always goes to the selected item, but it would matter if that ever changed.
