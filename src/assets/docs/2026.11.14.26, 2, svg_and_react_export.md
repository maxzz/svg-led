**User**

When a paste operation from the clipboard is performed, it is necessary to check whether the text being pasted is SVG or an SVG-based React component. If it is, the React component's properties must be converted into a CSS format and an HTML representation. Here is an example of such a React-based SVG:

<svg viewBox="0 0 24 24" fill="currentColor" stroke="currentColor" strokeWidth={1.5} strokeLinecap="round" strokeLinejoin="round" {...rest}>
	{title && <title>{title}</title>}
	<path d="M6 4 V20.4 L7 20.3 L11.4 15.5 L17.3 15.5 L17.1 14.9 L6.5 4.2 Z" />
</svg>

Properties that do not pertain to SVG or CSS can be skipped and ignored.
		
This functionality needs to be implemented as a modular, block-based system. 
In the future, additional similar blocks will be added to transform text pasted from the clipboard into a format compatible with the current application. 
For example, if only individual SVG elements—rather than a complete SVG file—are pasted, and the source text for an SVG file is not yet open in the editor, the system should wrap these elements back into an SVG element. 
Other similar scenarios—not yet defined—may arise later, but the architecture should allow for them to be added easily.

A similar filter architecture should also be implemented for export and copy operations; specifically, when exporting, the user should be able to specify the target format—or choose to copy to the clipboard—via a single dialog. 
To achieve this, an export dialog must be added, offering a selection of different formats along with a "Copy" button.

Export dialog should have preview of exported file.

For state management, the React components should use either Jotai or Valtio—
whichever is more appropriate—instead of standard state management provided by React.
This simplifies component reuse throughout the application.
Implement the new functionality in separate files/folders so that it does not mix with the rest of the code.
Minimize the use of `useCallback` and `useEffect` in React components in favor of Jotai’s `set` atoms and derived atoms (where necessary), or use Valtio’s reactivity where appropriate.

**Paste.** Ctrl+V, the "Paste SVG from clipboard" command, and dropping text on the canvas all go through one pipeline of small blocks in `src/transforms/1-paste/`. They run in this order:
1. **Extract markup:** pulls the `<svg>` (or bare elements) out of a whole component file, a Markdown code fence or surrounding text.
2. **JSX to SVG:**
   - `strokeWidth={1.5}` becomes `stroke-width="1.5"`, `className` becomes `class`, and style objects become CSS.
   - It drops `{...rest}`, `{title && …}`, event handlers and other values only known at run time.
   - `<Svg>`/`<Path>` from react-native-svg and `<motion.path>` are recognized too.
   - A notice tells the user a conversion happened.
3. **Empty canvas, whole `<svg>`:** it becomes the document, keeping its viewBox.
4. **Empty canvas, bare elements:** they are wrapped in an `<svg>` with the current viewBox.
5. **Keep root paint:** I added this one after browser testing showed a problem that was already in the app. Pasting a whole `<svg>` into a document kept only its children, so your example's `fill`, `stroke`, `stroke-width` and line caps (all on the root) were lost. They now go onto a wrapping `<g>`.

To add a new scenario, write one `{ id, label, apply }` block and add it to `PASTE_BLOCKS`. Monaco's own paste is unchanged, as you chose.
