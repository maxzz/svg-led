**Cursor**

**Save** (`file.save`, Ctrl+S) writes to the file you're already working on. **Save as** (`file.saveAs`, Ctrl+Shift+S) always asks where to put the file. **Export SVG** (`file.exportSvg`) doesn't involve the open file at all; it always downloads a copy.

They differ in how they pick the destination (`src/store/3-document/5-file-io.ts`):

- **`saveSvgFile()` (Save, line 48):** It uses `currentHandle` if one exists, which means the file was opened with the picker or saved before. In that case it overwrites that file in place with no prompt. If there's no handle yet (a new drawing, or a file loaded through the fallback input), it opens a "Save as" dialog. Where the File System Access API isn't available, it triggers a browser download instead.
- **`saveSvgFileAs()` (Save as, line 68):** It clears `currentHandle` and then calls `saveSvgFile()`, so the save dialog always appears and the chosen location becomes the new target for future Ctrl+S.
- **`exportSvgDownload()` (Export SVG, line 75):** It serializes the document and downloads it with `downloadBlob`. It never touches `currentHandle`, so the document stays linked to its original file, and it never writes over that file. It also doesn't return a result, so the command doesn't report "Saved".

The label on `file.save` says "Save to...", but in the common case it saves directly without asking. That label fits the first-save case better than the overwrite case, so you may want to change it to "Save".
