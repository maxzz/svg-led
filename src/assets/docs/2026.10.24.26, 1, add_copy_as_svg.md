It is necessary to add some enhancements to the SVG copy operation. 
This operation must take into account whether the "use viewbox" mode is enabled. 
If the "use viewbox" mode is active, the objects copied to the clipboard must be expressed in terms of the viewbox coordinates. 
If the "use viewbox" mode is disabled, a viewbox must be determined based on the selected objects bounding box (or, if no objects are selected, based on all objects).

This functionality needs to be implemented in such a way that it can later be used not only from the menu but also from the export dialog, which has not yet been implemented.

The SVG copy now respects the "Use viewBox" switch, and the linter and TypeScript check pass. I haven't tested it in the app.

- **"Use viewBox" on:** The copied SVG keeps the document's viewBox, so the coordinates match the viewBox. If the document has no viewBox, the content bounding box is used instead. Width and height are left as the document's own values.
- **"Use viewBox" off:** The viewBox is fitted to the bounding box of the selection, or of all top-level objects when nothing is selected, with 4 units of padding. Width and height are set to the viewBox size.

The core logic is `buildSvgExportText(ids, { useViewBox, padding? })` in `src/store/3-document/5-file-io.ts`. It returns the SVG text without touching the clipboard, so the export dialog can call it directly and pass its own `useViewBox` value. `copySvgToClipboard` is a thin wrapper around it. The menu command passes `appSettings.prefs.showViewBox`.
