**Cursor**

The layers panel uses a native `overflow-y-auto` scroller, so its scrollbar is styled by the browser unless there's global CSS. Checking for existing scrollbar rules.

Native scrollbars can't animate their width, so I'll use a CSS class that changes the scrollbar width on hover, and apply it to the layers tree scroller.

I made the layers panel scrollbar thin by default and widen it while the mouse is over the panel's tree. I haven't run the app to check it visually.

**What changed:**
- **`src/assets/styles/index.css`**: added a `.thin-scrollbar` class. By default the scrollbar is 6px wide with a semi-transparent thumb, and it grows to 12px when the container is hovered. The thumb also darkens on its own hover. Both light and dark themes use the existing `--muted-foreground` color.
- **`src/components/1-workspace/6-layers-panel/0-layers-panel.tsx`**: added `thin-scrollbar` to the `TreeScroller` element, which is the scrolling container for the layers list.

**Limitations:**
- **No animation.** Browsers don't animate native scrollbar width, so it snaps between sizes. A smooth grow would need a custom scrollbar built from JS or a Radix `ScrollArea`, which is a bigger change.
- **Hover area is the whole list, not just the bar.** Native CSS can't target the scrollbar alone, so moving the mouse anywhere over the layers list expands it.
- **Content shifts by about 6px on hover.** The rows get narrower when the bar grows. I can reserve the space if that's noticeable.
- **Firefox gets a static thin bar.** It doesn't support hover-resizing, so it stays thin all the time.

If you want the bar to be hidden until hover, or want the same treatment for the other scrollable panels, I can extend it.
