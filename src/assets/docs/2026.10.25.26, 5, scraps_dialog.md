**How the dialog works** (it follows your `svg-path26` open and save dialogs, combined into one):
- **Saved scraps list:** newest first. Each row shows a preview thumbnail, the name, the element count and the date, plus a delete button on hover. Double-click or Enter loads a scrap, and the arrow keys move through the list.
- **Load:**
  - "Add to canvas" puts the scrap's elements on top of the canvas and selects them.
  - "Replace canvas" swaps the whole canvas for the scrap, restores the viewBox it was saved with, and zooms to fit.
  - Both can be undone with Ctrl+Z.
- **Save as scrap:** it has a name field (defaults to "Scrap N") and a "Selected (n) / All (n)" choice; "Selected" is disabled when nothing is selected. Clicking a saved scrap copies its name into the field. Saving over an existing name shows a warning and asks for confirmation first.
- The dialog remembers your load mode and save scope between sessions.

**How scraps are stored:**
- Scraps have their own localStorage key (`svg-led__scraps__v1`) instead of sharing the main settings object, because they can get large. If storage is full, you get an error toast and the list stays unchanged.
- Each scrap holds the elements' SVG markup, which keeps every attribute (fill, stroke, dash, opacity and so on). It also keeps the document's viewBox and root `<svg>` attributes from when it was saved. I took these to be the "associated options".
- The same markup is used for the thumbnail, with a viewBox fitted around the elements. Element coordinates are unchanged, so "Add to canvas" puts them back exactly where they were.
- I also registered a "Scraps..." command, so it shows up in the command palette.

The dialog is in the new `src/components/4-dialogs/8-9-scraps/` folder, with the save, load and delete logic in `9-types-scraps.ts`. The other changes are small edits to the commands list, the More tools menu, the dialog mount, the storage keys and the confirmation messages.
