# Selection tool update issue
_Exported on 11/13/2026 at 19:33:54 PST from Cursor (3.30.14)_

---

**User**

When using the Select Tool, objects that are even partially touched by the selection area are included in the selection. 
However, if you hold down the Control key, only objects that fit entirely within the selection frame are included. 
The issue is that when the Control key is pressed, the selection does not update immediately; the user have to move the mouse before the elements within the selection area are updated. 
The selection should update the moment the Control key is pressed—without requiring any mouse movement—and it should also update when the Control key is released.

---

**Cursor**

Let me look at the select tool's marquee logic and how it handles modifier keys.

The marquee selection is only recomputed in `onPointerMove`, so a modifier key change has no effect until the pointer moves. I'll store the last pointer event on the marquee gesture and re-run the selection from the key handlers.

Now I'll check the types and lints.

Ctrl now updates the marquee selection as soon as it's pressed or released, even if the mouse hasn't moved. The TypeScript check passes and the linter is clean. I haven't run it in the app, so the live behavior is untested.

The fix is in `src/tools/tool-2-select/0-factory-select.ts`:

- **Remember the last pointer event.** The marquee gesture now keeps the most recent pointer event, so the selection can be recalculated without a mouse move.
- **Recalculate on key changes.** A new `refreshMarquee` helper runs from the select tool's `onKeyDown` and `onKeyUp`. It re-runs the same selection logic as a pointer move, using the current Ctrl/Shift/Alt state.

Alt also switches between the rubber band and the lasso mid-drag, and that switch used to wait for a pointer move too. It now updates on key press and release as well, the same way as Ctrl. Shift is also recalculated; it has no effect on marquee selection, so it changes nothing there.
