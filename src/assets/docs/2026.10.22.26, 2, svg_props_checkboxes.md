The attached screenshot of the "Properties" popup shows an additional column on the left.

This additional column should be quite narrow and not take up much width; the checkboxes themselves should also be fairly small, as they 
serve an auxiliary purpose and should not distract from the main properties. 
For each property that can be represented in the SVG format, there is a corresponding checkbox. 

If a checkbox is selected, the value of that property will be written to the SVG file; if it is deselected, the property will be omitted from the SVG file. 
The initial state of these checkboxes is determined by the existing SVG file. 
Group properties also have checkboxes (for example "Line caps and joins"); however, if the checkboxes within a group have mixed states 
(i.e., some are selected while others are not), the group-level checkbox will display a square instead of a checkmark. 
If all checkboxes within a group are selected, the group-level checkbox will appear as selected. 
In short, the group-level checkbox functions as a tri-state indicator: selected, deselected, or in an "indeterminate" (mixed) state.

Previously, an option was added to control the export of values that are "none"; this option needs to be removed from the code, as it will now be implemented using checkboxes. 
However, the tab "Export" itself should not be removed entirely, as other settings will be added to it later.
