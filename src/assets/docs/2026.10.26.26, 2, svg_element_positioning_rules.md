# SVG element positioning rules
_Exported on 10/26/2026 at 19:54:18 PDT from Cursor (3.27.14)_

---

**User**

When a HTML tags 'defs' and a 'style' are present in an SVG file, they should be positioned at the top; accordingly, the "Bring to Front" and "Send to Back" commands should move elements behind these items, rather than in front of them.

---

**Cursor**

Now I'll make the reordering operate only on the movable siblings and keep the pinned ones at the top.

Z-order commands now leave `defs` and `style` at the top of their parent, so "Bring to Front" and "Send to Back" place elements just after them rather than above or below them.

The change is in `src/store/3-document/4-doc-actions.ts`:

- **`isPinnedNode`** (new helper) identifies passthrough elements whose tag is `defs` or `style`. It ignores any namespace prefix and is case-insensitive.
- **`reorderNodes`** skips pinned nodes when collecting the selection, so they can't be moved. It also reorders only the movable siblings, then writes the pinned nodes back first. This applies to all four directions, so "Bring forward" and "Send backward" can't swap an element past them either.

The linter reports no errors. I haven't run the app or the test suite, so this is untested. Selecting a `defs` or `style` node and then running a z-order command is a no-op for that node.
