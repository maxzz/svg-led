# Direct selection cursor design
_Exported on 11/4/2026 at 17:39:28 PST from Cursor (3.28.7)_

---

**User**

In "Direct Selection" mode, when the cursor is positioned over a path point, it should take the form of an unfilled triangle (the standard cursor appearance for this mode), with a small, unfilled square added to its bottom-right corner.

---

**Cursor**

I'll start by finding the existing cursor definitions and the Direct Selection tool.

The Direct Selection cursors live in `tailwind-cursors.ts`, and `pointsCursorClass` picks them. Right now hovering a path point (`anchor`) returns the four-way move cursor. I'll add a new arrow-plus-hollow-square cursor for anchors and route anchor hover to it. Ctrl (delete), Alt (convert), drag, and handle hover keep their current behavior.

Now I'll run the points-cursor tests and the linter on the changed files.

Hovering a path point in Direct Selection now shows the unfilled-triangle arrow with a small unfilled square at its lower right.

The change:

- **`src/ui/cursors/tailwind-cursors.ts`**: added a `directPointMark` drawing (a hollow square with a 1px white border and 1px black edge) and a new `.cursor-direct-point` class that combines it with the existing arrow.
- **`src/tools/tool-3-points/2-points-cursor-class.ts`**: anchor hover now returns `cursor-direct-point`. Previously it returned the four-way move cursor. Handle hover, dragging, Ctrl (delete), and Alt (convert) are unchanged.
- **`src/tools/tool-3-points/tests/points-cursor.test.ts`**: updated the anchor expectation. The three tests pass and the linter reports no errors.

I haven't looked at the cursor in the running app, so the square's exact size and position are untested visually. If it needs adjusting, the coordinates are in `directPointMark`.
