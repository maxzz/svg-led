**Cursor**

The conversion happens in `paintValue`, which currently emits every color as an arbitrary value (`fill-[#fff]`). I'll add a lookup for the white and black hex values.

`in` checks the prototype chain too, so a value like `constructor` would hit `Object.prototype`. I'll switch to an own-property check.

I updated `src/transforms/2-export/1-tailwind-classes.ts` so that white and black hex colors export as palette names when the Tailwind classes option is on:

- `fill="#fff"` and `fill="#ffffff"` become `fill-white`
- `fill="#000"` and `fill="#000000"` become `fill-black`
- `stroke` gets the same mapping, since it uses the same color path

The matching is case-insensitive, so `#FFF` also maps to `fill-white`. Other colors still export as arbitrary values such as `fill-[#ff0000]`.

I only checked for lint errors. I haven't run the export dialog or the test suite to confirm the output end to end.

The change only covers colors that come from the element's `fill` and `stroke` attributes. If your input SVG already has `fill-[#fff]` written into its `class` attribute, that class is passed through unchanged. Tell me if you want those rewritten too.
