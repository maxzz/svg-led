# Help dialog escape behavior
_Exported on 10/28/2026 at 19:55:46 PDT from Cursor (3.27.22)_

---

**User**

In the Help dialog, when the focus is in the command search field and a value has been entered (and not in the 'Record keys'  mode), the first press of the Escape key should clear that value; only when the search field is empty should pressing Escape close the dialog.

---

**Cursor**

I'll look at how the Help dialog handles Escape in the command search field so the first press clears a value and only an empty field closes the dialog.

Escape currently closes the dialog even with text in the search field. I'll check how the dialog and search field handle that key so the first press clears the value instead.

Escape is handled on the dialog before the field sees it, so a filled search field closes immediately. I'll make that first press clear the text, and close only when the field is already empty.

With the command search field focused, the first Escape now clears a typed value, and a second Escape closes the Help dialog.

- A name search such as `zoom` clears on the first Escape and the dialog stays open.
- Escape closes the dialog only when that field is already empty.
- Record keys mode is unchanged: the first Escape is recorded, and a second Escape in a row leaves that mode.
- Escape still closes the dialog immediately when focus is somewhere else, even if the field has text.
