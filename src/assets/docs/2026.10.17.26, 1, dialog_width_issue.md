The base `DialogContentClasses` includes `md:w-full`. Your `w-[min(...)]` only overrides the unprefixed `w-full`, so at `md` and wider the `md:w-full` rule still wins and the dialog stretches to the viewport. I'll make the width important, matching the `p-0!` and `max-w-none!` style already in this className.

The dialog should now be capped at 40rem wide on desktop instead of spanning the viewport.

**Cause:** `DialogContentClasses` in `src/ui/shadcn/dialog.tsx` includes `md:w-full`. Your `w-[min(...)]` overrode only the base `w-full`, so from the `md` breakpoint up, `md:w-full` still applied. The `tailwind-merge` step in `cn()` doesn't resolve this because the conflicting class has a variant prefix.

**Fix:** In `0-options-dialog.tsx`, I added the `!` suffix to the width class, so it reads `w-[min(40rem,calc(100vw-2rem))]!`. This is the same pattern as your existing `p-0!` and `max-w-none!`. I haven't run the app to check it visually.
