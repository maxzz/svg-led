No, I wouldn't switch to `NumberField`. I haven't changed anything.

`Controls_SvgSize` needs to accept things `NumberField` can't handle:

- **Units and keywords:** width and height can hold values like `24px`, `100%`, or `auto`. `NumberField` only takes a `number` and calls `Number(raw)`, so `"24px"` is rejected and the typed text is silently dropped.
- **Clearing the attribute:** an empty field has to remove the `width`/`height` attribute. `NumberField` ignores empty input, so the value can't be cleared.
- **Rounding and clamping:** `NumberField` rounds to `precision` (2 decimals by default) and applies `min`. That would change values the user typed in the SVG root attributes.
- **Placeholder:** `NumberField` only shows `''` or `Mixed`, while this field shows `auto` when the attribute is unset.

Making `NumberField` handle all of this would mean changing a shared control used across the properties panel, so keeping the text field local to the size section is the safer option.
