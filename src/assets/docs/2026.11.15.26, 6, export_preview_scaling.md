# Export preview scaling
_Exported on 11/15/2026 at 19:16:44 PST from Cursor (3.30.14)_

---

**User**

When a preview PNG is selected in the export dialog, it should be displayed at a one-to-one scale. If it is too large to fit within the designated preview area, it will be scaled down; however, it will never be scaled up. 
In other words, the amount of space occupied by the preview should remain constant.	
This is necessary to ensure that the preview does not appear blurry, as shown in the attached screenshot.

---

**Cursor**

The frame is currently sized to fill the preview area, so a 48 px PNG gets stretched up to about 170 px. I'll add a flag for PNG frames and cap their width at the bitmap's pixel width.

A PNG preview in the export dialog is now shown at its pixel size. It only shrinks when the preview area is too small, and it never scales up.

The change is in two files:

- **`9-atoms-export.ts`**: `ExportFrame` has a new `oneToOne` flag. It is `true` for PNG and `false` for the SVG, React, and data URI formats.
- **`2-export-preview.tsx`**: for PNG frames, the width is now `min(<pixel width>px, <fit size>)`. The fit size is still the largest frame with the export's aspect ratio that fits the preview area. So a 48 px PNG stays 48 px wide, and a 1000 px PNG shrinks to fit.

The type check passes. I haven't opened the dialog in a browser to confirm the look.

I left the SVG, React, and data URI formats alone, since they are vector and have no pixel size. Their frame still fills the preview area. If you want the same fixed size there, I can apply the cap to them as well.
