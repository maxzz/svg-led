Yes, a single provider is the better design. Each `TooltipProvider` creates its own tooltip group, so the per-label wrapper has no benefit and some cost.

**Why it matters**

- **Skip delay is per provider.** Radix's `skipDelayDuration` lets the tooltip open instantly when the user moves from one trigger to another within the same provider. With a provider per icon, every tooltip is its own group, so the "already open, hover the next one" behavior never happens.
- **Wrapping is redundant.** The provider is only a context. Rendering one per help icon creates many contexts for no benefit.
- **The tooltip still needs a provider somewhere.** Radix's `Tooltip` requires an ancestor `TooltipProvider`. Your `OptionTip` works only because it wraps itself. If you remove that wrapper, `OptionTip` will throw wherever no ancestor provides one.

**Recommended change**

1. Put one `TooltipProvider` higher up, around the options dialog content (or the app root, since `4-welcome-footer.tsx` also uses one). Your `src/ui/shadcn/tooltip.tsx` already defaults `delayDuration` to 0.
2. Remove the `<TooltipProvider>` wrapper from `OptionTip` so it only renders `Tooltip`, `TooltipTrigger`, and `TooltipContent`.

If you go with the app root, the welcome footer's provider can also be removed, which leaves one provider for the whole app. If you prefer to keep `OptionTip` self-contained, you can leave the provider in it. That's acceptable for a standalone component, but it does lose the shared skip-delay behavior across the options list.
