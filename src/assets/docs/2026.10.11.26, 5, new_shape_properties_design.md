# New shape properties design
_Exported on 10/11/2026 at 20:30:11 PDT from Cursor (3.24.12)_

---

**User**

The properties for a new shape are currently inherited from the previously selected shape, but this has proven inconvenient for the user experience. 

A different approach is needed for the properties applied to new shapes; specifically, when a tool for creating a new shape—such as 
a rectangle or a circle—is selected, there should be a single set of value properties used for all new shapes.	

Initially, this set of settings determines the default properties (or saved from previous session); however, when the tool for creating a new shape is selected, all properties applicable to that shape must appear in the properties panel. 
If the user changes a value—for instance, switching the stroke color from the default black to green—the new rectangle must use a green stroke. 
If the user selects a stroke width before creating a new shape, that width will apply to all subsequent new shapes until the user explicitly changes a property before creating another one.

In other words, when a form is selected, the properties panel displays the properties for that form; 
however, when the tool for creating a new form is selected, the properties used should be those that were previously set for creating that new form.

For example, when the "Create Rectangle" tool is selected, only the stroke , fill, and stroke width are currently displayed; 
however, this is incorrect—the list is missing other parameters applicable for the rectangle such as stroke style, corner radius, caps, and joints settings.

If they are displayed in the properties panel, the user will be able to set the required property before starting to create a new primitive.

And these modified properties will be used to create subsequent new forms—meaning there is no link to the last selected model, unlike the previous approach, which was a flawed decision.

A logical solution would likely be to have a single object containing all possible properties for all new primitives; 
depending on the selected tool, only those properties applicable to the new primitive would be displayed and used. This entire object should be stored in LocalStorage.
This is a rather significant and important change, so if you have any questions, feel free to ask.

**What changed**

- **One object, one localStorage key.** `newShapeStyleAtom` holds stroke, fill, stroke width, dash style, custom dash, caps, joins, opacity, and corner radius under `svg-led__new-shape__v1`. It replaces the four separate atoms and their keys. The old saved values are migrated once on first load, then the old keys are removed.
- **Select-mode edits no longer touch the defaults.** I deleted `5-style-from-selection.ts`, so a selected shape no longer changes what the next shape looks like.
- **The creation-tool panel shows the new-shape values.** It reuses the same section list as the selection panel, filtered by shape kind:
  - Rectangle: stroke, fill, width, dash, caps/joins, opacity, corner radius.
  - Ellipse: same, without corner radius.
  - Line: no fill, no corner radius.
  - Pen: same as rectangle, without corner radius.
- **Each section writes to one target.** A section either edits the selection or the new-shape defaults, depending on the panel it's in. Position and actions are hidden in the creation panel.
- **Shape tools read the same object.** The rectangle, ellipse, line, and pen tools all create shapes from `newShapeStyleAtom`.

**One behavior change to be aware of:** while a creation tool is active, the panel always shows the new-shape values, even when a shape is selected. If the tool is locked and you draw a rectangle, the panel stays on the rectangle defaults. To edit that rectangle's properties, switch to Select.
