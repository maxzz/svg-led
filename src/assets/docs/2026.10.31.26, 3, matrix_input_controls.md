The matrix row belongs in Position and size, and it should only show when the selection actually has a transform. I’ll keep that logic in its own folder, with Jotai for the field and Motion for the row.

The matrix row now sits in **Position and size**, and it only appears when the current selection has a transform matrix. It slides open and closed with Motion.

The field has no label. A help icon at the end of the input explains the six numbers `a b c d e f`. You can type a `matrix(...)`, six numbers, or an SVG transform such as `rotate(45)`. Enter or leaving the field writes that matrix onto the selection. An invalid value stays in the field and shows a warning.

Two buttons follow the field:

- **Apply** writes the matrix into the points and then removes it. A rotated rectangle becomes a path. A group's matrix is pushed into its children. Text and images are left alone, because they have no points to rewrite, and the button is disabled for them.
- **Remove** deletes the matrix and leaves the points where they are, so the element jumps back to its untransformed place.

The row reads the document and the selection through Jotai atoms, so it can be dropped in anywhere without its own React state. The new code lives in `src/components/1-workspace/2-props-panel/6-matrix-input/`.

I checked it on a selected rectangle: with no matrix the row stays hidden. After a rotation it shows the matrix, Apply turns the rectangle into a path and the row leaves, and Remove drops the matrix while the rectangle's own x, y, width, and height stay the same.
