**Cursor**

I'll look at the Scraps dialog and the Layers panel drag-and-drop so the Scraps list can use the same Motion pattern.

The Layers panel drags with a Motion ghost and a springy insertion line, and waits a few pixels so clicks still work. Scraps will follow that, and the saved order will stick instead of jumping back to newest-first.

The scroll viewport’s props don’t accept a data attribute, so the drag handler will take the viewport element directly.

The list uses pointer dragging, same as Layers, so a native drag won’t start it. I’ll keep the gesture going even if pointer capture isn’t available, then drive it with pointer events.

Scrap rows in the Scraps dialog can now be dragged to a new position, using the same Motion gesture as the Layers panel.

Drag a row and a label follows the pointer. A line shows where the scrap will land and glides between rows. The row you are dragging fades until you drop it. The new order is saved in browser storage and is still there after a reload. A short click still selects a scrap, and a double-click still loads it — the drag starts only after the pointer moves a few pixels. The delete button does not start a drag.

New scraps are still inserted at the top. Saving over an existing name keeps that scrap where it already sits. Scraps saved before this change still open newest first until you reorder them.
