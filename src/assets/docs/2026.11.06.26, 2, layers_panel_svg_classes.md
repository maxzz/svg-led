**Cursor**

I haven't changed any code. Here are the options and how they compare.

Your diagnosis is right. A `<defs>` element and its children are never drawn directly. They only take effect when something references them, such as `fill="url(#grad)"`, `clip-path`, `mask`, or `filter`. `display` doesn't apply to gradients, clip paths, masks, filters, or markers, so setting it does nothing. The only thing that changes the rendering is breaking the reference.

**Options:**

1. **Rename the id** (`grad` becomes `deactivated-grad`), the same approach as classes. It's reversible, shows up in the tree, and children need no special handling because they have no ids of their own. The catch is that references to the old id now dangle, and browsers handle a dangling reference differently per property. A dangling `fill` renders nothing, but a dangling `clip-path` usually leaves the element unclipped, which is the opposite of what we want.

2. **Comment out the element** in the source, for example `<!-- <linearGradient id="grad">…</linearGradient> -->`. It's the most literal "off" and easy to read, and uncommenting restores it. The downsides: the source scanner ignores comments, so the tree would need a separate parser for commented items. XML doesn't allow `--` inside a comment, so some content would need escaping. And references dangle just as in option 1.

3. **Park the element in app state** and remove it from the file. The output stays clean, but the deactivated state isn't in the file, so it's lost on reload and when the file is copied. I wouldn't recommend it for a source-based editor.

4. **Rewrite every reference to `none`** and keep the original value in a marker so it can be restored. This gives predictable rendering in every browser, but it edits shape attributes and makes undo and reactivation more complex.

I'd suggest option 1, with references rewritten to `none` (option 4) only if the dangling-reference behavior turns out to matter in practice. In either case, deactivating a `defs` item should apply to all of its descendants, as you said.
